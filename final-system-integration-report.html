This official integration report covers the structural mapping, domain matching, payment webhooks, and generative AI execution architectures of the MyApproved.com UK verified tradesperson platform, along with details of the fully operational **GoLang Backend API Platform** written to repair all legacy bottlenecks.

1. Deep Discovery Audit & Codebase Mapping

1.1 Entrypoint & Routing Workflow

The core client platform runs on **Next.js 14** using the **App Router** paradigm. User actions (quote estimates, job postings, trade sign-ups) execute through components under `/components/` and are processed via Route Handlers under `/app/api/`.

  • Job Submission: Users post jobs using components/AIQuoteForm.tsx or components/JobPostForm.tsx, which targets the route handler app/api/jobs/submit/route.ts.
  • Supabase Integration: Jobs are written directly to Supabase PostgreSQL, and are synced downstream to the CRM.

1.2 GHL Contact Sync Diagnostics

The prior sync between Next.js and GoHighLevel (GHL) was failing because of an environment variable mismatch. The root configuration utilized GHL_API_KEY and GHL_LOCATION_ID, while the route handler expected GOHIGHLEVEL_API_KEY and GOHIGHLEVEL_LOCATION_ID, rendering the CRM sync module disabled by default.

Furthermore, GHL's newer V2 API endpoints (e.g. /contacts/search) were poorly aligned with the raw fields captured during client submission.

1.3 Notification & Postcode Radius Proximity Matching

The platform's verified tradespeople alerts are powered by geographical proximity. UK Postcodes are mapped to defined regions in lib/utils/postcode-matcher.ts.

  • Proximity scoring (0-100) measures geographical distance based on postcode area prefixes (e.g. ST).
  • An exact prefix match yields a score of 100, regional matches are scored at 75, and adjacent regions (such as London and the South East) score 50. This cleanly matches candidates inside a defined geographical boundary.

1.4 Monetization & Gated Leads Gating

Job leads are gated using the lead_purchases schema in Supabase:

  • Unsubscribed tradespeople receive masked job details and a masked client phone number (e.g., 077xxxxxx78).
  • Unlocking requires a £4.99 transaction. Previously, this occurred exclusively via a Stripe Checkout Session. Under GHL-native monetization, GHL native payment triggers are processed via webhooks which update the matching row to paid in Supabase, instantly exposing the unmasked details.

2. Modular Go Backend Architecture

To resolve these legacy constraints, a high-performance, compiled Go backend application was engineered in the workspace root. It serves as a unified, type-safe API platform running on Port 8080.

main.go

Acts as the central server engine. Loads env keys, bootstraps the HTTP router, configures logging middleware, and handles CORS headers (including preflights). Exposes API pathways.

ghl.go

Coordinates GoHighLevel V2 CRM operations. Resolves Bearer tokens, searches for existing contacts by email, creates or updates contact records, and registers opportunities in sales pipelines.

geomatch.go

Implements a UK postcode matching engine. Maps postcode prefixes to regional buckets, grades geographical proximities, and queries Supabase to pull and filter candidates.

alerts.go

Handles alerts and masking. Includes a UK phone masking function, an SMTP email alert dispatcher, and records leads under the lead_purchases table.

gemini.go

Calculates quote estimates. Integrates the official google.genai SDK with a robust HTTP REST fallback, using custom prompts to guarantee a strict JSON output matching the UI schema.
